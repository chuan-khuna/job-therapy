# 03: Alembic migrations replace create_all

Status: ready-for-agent
Type: task
Blocked by: 01, 02

## What

- Add Alembic with `uv add alembic` and run `alembic init` under `backend/`, for example `backend/migrations/`.
- `env.py` reads `DATABASE_URL` from the same settings as the app, sets `target_metadata = SQLModel.metadata` after importing `app.models`, and imports `sqlmodel` in the script template so autogenerated revisions work.
- Store `created_at`/`updated_at` as `timestamptz` (`sa_column=Column(DateTime(timezone=True))`). Keep the UTC `…Z` `field_serializer` in the read schemas.
- Autogenerate a baseline revision for the existing `results` table and review it by hand.
- Remove `init_db()` / `create_all` from the app lifespan. The schema is now managed only by migrations.
- Add `just` recipes:
  - `backend-migrate`: `alembic upgrade head`
  - `backend-revision msg=...`: `alembic revision --autogenerate -m`

## Acceptance

- On a fresh local DB, `just backend-migrate` creates `results`.
- Posting and reading results through the API works end to end.
- Running `alembic check` right after reports no diff.
